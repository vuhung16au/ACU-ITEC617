# ANSI SQL

## Overview
This document provides a concise introduction to ANSI SQL, explaining what it is, why it is important in modern database development, and how it differs from proprietary dialects such as Microsoft's T-SQL (Transact-SQL).

## What is ANSI SQL?
**ANSI SQL** (American National Standards Institute Structured Query Language) is the standardized database query language. First established in 1986, it was created to ensure consistent database management and interoperability across various Database Management Systems (DBMS).

ANSI SQL defines the standard syntax and rules for:
* **DDL (Data Definition Language):** `CREATE`, `ALTER`, `DROP`
* **DML (Data Manipulation Language):** `SELECT`, `INSERT`, `UPDATE`, `DELETE`
* **DCL (Data Control Language):** `GRANT`, `REVOKE`
* **TCL (Transaction Control Language):** `BEGIN`, `COMMIT`, `ROLLBACK`

## Why ANSI SQL?
Using ANSI SQL, particularly modern standards like ANSI JOINs, provides several key benefits:

* **Standardization & Portability:** Code written in ANSI SQL can run on almost any major relational database (PostgreSQL, MySQL, Oracle, SQL Server) with minimal to no modifications, avoiding vendor lock-in.
* **Readability:** Explicit syntax, such as using `INNER JOIN ... ON`, cleanly separates the join logic from filtering logic (the `WHERE` clause), making queries easier to read and maintain.
* **Error Prevention:** ANSI joins require an explicit `ON` condition. If omitted, the database engine throws an error. Legacy implicit joins (e.g., `FROM table1, table2`) without a `WHERE` clause would silently perform a resource-heavy cross join (Cartesian product).
* **Foundation for Learning:** Mastering ANSI SQL provides a solid foundation before moving on to database-specific procedural extensions.

## (Brief) Comparison between ANSI SQL and T-SQL

While **ANSI SQL** is the universal standard, **T-SQL (Transact-SQL)** is Microsoft's proprietary extension of SQL designed specifically for Microsoft SQL Server and Azure SQL Database. T-SQL includes all the capabilities of ANSI SQL but adds procedural programming features and specialized functions.

### Key Differences

| Feature | ANSI SQL | T-SQL (Transact-SQL) |
| :--- | :--- | :--- |
| **Type/Origin** | Universal standard by ANSI/ISO. | Proprietary extension by Microsoft. |
| **Procedural Logic** | Originally declarative only. Recent standards (SQL:1999) added procedural elements, but implementation varies by DBMS. | Includes built-in procedural elements like `IF/ELSE`, `WHILE` loops, `TRY...CATCH` blocks, and variables (`DECLARE`). |
| **Null Handling** | `COALESCE(col1, 'default')` | `ISNULL(col1, 'default')` (also supports `COALESCE`) |
| **Current Date/Time**| `CURRENT_DATE`, `CURRENT_TIMESTAMP` | `GETDATE()`, `SYSDATETIME()` |
| **String Concatenation**| `||` operator (e.g., `first_name || ' ' || last_name`) | `+` operator or `CONCAT()` function. |
| **Limiting Results** | `FETCH FIRST 10 ROWS ONLY` (SQL:2008) | `SELECT TOP (10) ...` |

### Syntax Examples

#### 1. Conditional Logic
**ANSI SQL (Standard `CASE`):**
```sql
SELECT 
    employee_name,
    CASE 
        WHEN salary > 50000 THEN 'High'
        ELSE 'Normal' 
    END AS salary_band
FROM employees;
```

**T-SQL (Procedural `IF...ELSE` in a script):**
```sql
DECLARE @salary INT = 60000;
IF @salary > 50000
    PRINT 'High Salary';
ELSE
    PRINT 'Normal Salary';
```

#### 2. String Concatenation & Date
**ANSI SQL:**
```sql
SELECT first_name || ' ' || last_name AS full_name, CURRENT_TIMESTAMP
FROM employees;
```

**T-SQL:**
```sql
SELECT first_name + ' ' + last_name AS full_name, GETDATE()
FROM employees;
```

## Conclusions
* **ANSI SQL** is the foundational standard that ensures SQL scripts are portable, robust, and readable across different database systems.
* **T-SQL** extends ANSI SQL to give developers powerful procedural and application-development features within the Microsoft SQL Server ecosystem. 
* **Best Practice:** Always use ANSI SQL syntax (especially for JOINs) for standard queries to maximize portability. Rely on T-SQL specific features only when building complex scripts, stored procedures, or triggers specifically intended for SQL Server environments.
