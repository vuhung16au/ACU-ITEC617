# Sample Database Schemas

This document provides a collection of sample database schemas, designed to introduce the structure of databases and tables based on real-world business rules and use cases.

For each example, we'll start with the **Business Rules** or **Use Case**, and then present the corresponding **Database Schema** (the structure of the tables required to satisfy those rules).

---

## 1. University System

### Use Case & Business Rules
A university needs to manage its students, teaching staff, and course enrollments. 
- A **Student** can enroll in many **Courses**.
- A **Course** can have many **Students** enrolled.
- A **Lecturer** can teach multiple **Courses**, but a course is taught by one primary lecturer.

### Database Schema

* **`students`**
  * `student_id` (Primary Key)
  * `first_name`
  * `last_name`
  * `date_of_birth`
  * `enrollment_year`

* **`lecturers`**
  * `lecturer_id` (Primary Key)
  * `first_name`
  * `last_name`
  * `department`
  * `email`

* **`courses`**
  * `course_code` (Primary Key)
  * `course_name`
  * `credits`
  * `lecturer_id` (Foreign Key referencing `lecturers`)

* **`enrollments`**
  * `enrollment_id` (Primary Key)
  * `student_id` (Foreign Key referencing `students`)
  * `course_code` (Foreign Key referencing `courses`)
  * `semester`
  * `grade`

## 2. Online Store

### Use Case & Business Rules
An e-commerce platform needs to track its customers, the products it sells, available inventory, and customer orders.
- A **Customer** can place many **Orders**.
- An **Order** belongs to one **Customer**.
- An **Order** can contain many **Products**, and a **Product** can appear in many **Orders**.
- **Inventory** must track the stock levels of each product.

### Database Schema

* **`customers`**
  * `customer_id` (Primary Key)
  * `first_name`
  * `last_name`
  * `email`
  * `shipping_address`

* **`products`**
  * `product_id` (Primary Key)
  * `name`
  * `description`
  * `price`

* **`inventory`**
  * `inventory_id` (Primary Key)
  * `product_id` (Foreign Key referencing `products`)
  * `quantity_in_stock`
  * `last_restocked_date`

* **`orders`**
  * `order_id` (Primary Key)
  * `customer_id` (Foreign Key referencing `customers`)
  * `order_date`
  * `total_amount`
  * `status` (e.g., Pending, Shipped, Delivered)

* **`order_items`** (Junction Table for Orders and Products)
  * `order_item_id` (Primary Key)
  * `order_id` (Foreign Key referencing `orders`)
  * `product_id` (Foreign Key referencing `products`)
  * `quantity`
  * `unit_price`

## 3. Library Management System

### Use Case & Business Rules
A local library needs to keep track of its books, members, authors, and the borrowing history (loans).
- An **Author** can write many **Books**, and a **Book** can have multiple **Authors**.
- A library **Member** can borrow many **Books** over time.
- A **Loan** records which member borrowed which specific book copy and when it is due.

### Database Schema

* **`authors`**
  * `author_id` (Primary Key)
  * `first_name`
  * `last_name`
  * `biography`

* **`books`**
  * `book_id` (Primary Key)
  * `title`
  * `isbn`
  * `publication_year`
  * `genre`

* **`book_authors`** (Junction Table for Books and Authors)
  * `book_id` (Foreign Key referencing `books`)
  * `author_id` (Foreign Key referencing `authors`)
  * Primary Key: (`book_id`, `author_id`)

* **`members`**
  * `member_id` (Primary Key)
  * `first_name`
  * `last_name`
  * `email`
  * `join_date`

* **`loans`**
  * `loan_id` (Primary Key)
  * `book_id` (Foreign Key referencing `books`)
  * `member_id` (Foreign Key referencing `members`)
  * `borrow_date`
  * `due_date`
  * `return_date` (NULL if not returned yet)
